# BME native isolation evidence, 2026-11-03

Executed on `bclab-runner` (`cloud-29136`) through existing SSH access. Ubuntu
24.04.4 x86-64, 8 vCPU, 15 GiB RAM, systemd 255, bubblewrap 0.9.0, nftables 1.0.9.
No nested KVM device or CPU virtualization flags were exposed. Root-managed Linux
namespaces worked. QEMU packages were installed during the initial alternative
probe, then removed after the user requested minimal performance loss. No QEMU
job was launched. The `cpio` security package update from that transaction remains.

The executable evidence is `verify.py` alongside this file, using the installed
`sandbox.py`, `trusted.conf`, AppArmor profile and egress policy in this same Git
revision. The final installer was also exercised in dry-run and idempotent apply
modes. This report records live results, not merely unit-test assertions.

## Observed controls

| Probe | Result |
| --- | --- |
| Root inside namespace versus actual host UID | Live sandbox payload processes had non-root host UIDs allocated by systemd. |
| Concurrent job filesystem separation | Job B could not see markers created by A in `/work` or `/tmp`. |
| Concurrent process separation | Host/controller and job A host PIDs were absent from B's `/proc`. |
| Host credentials and inherited environment | Root-only host canary, both runner credential paths, SSH home and injected `GH_TOKEN` canary absent; host canary unchanged. No real secret content read. |
| Host filesystem and privilege escalation | `/usr` read-only; effective capabilities zero; no-new-privileges set; mount and nested user-namespace attempts denied. |
| Network boundary | B could not reach A's loopback listener, a real host loopback listener, host SSH, IPv4 metadata/public HTTPS or IPv6 loopback/public HTTPS. |
| Normal completion with detached child | Background `sleep` did not survive; transient cgroup removed. |
| Cancellation | Stopping the named unit removed its cgroup and processes. |
| External timeout | A 30-second sleep with a 2-second deadline failed and its cgroup disappeared. |
| Memory limit | 256 MiB allocation under a 64 MiB cap failed; cgroup removed. |
| Killed controller | SIGKILL of the Python controller did not defeat the independent 3-second deadline; cgroup disappeared. |
| Live trusted runner | Connected and listening as UID 996 (`tdk-ci`), capabilities zero, no-new-privileges set. Its mount namespace denied the cloud SSH home and host `/etc` writes; sudo failed. |
| Live runner egress | GitHub HTTPS returned 200. Host/loopback SSH, metadata and public HTTP were denied. SSH access as `cloud` remained usable. |
| Residue | No `tdk-sandbox-*` units remained after verification. |

The AppArmor restriction on unprivileged namespace setup and a proc-mount conflict
with extra outer systemd proc restrictions were observed and fixed in the
launcher. A live-service permission probe initially treated `PermissionError` as
a test error; it now correctly counts inaccessible host paths as denied. The final
probe suite passed. The systemd exposure score was 3.1, but that score is not used
as proof of cross-job isolation.

## Small performance observation

Three SHA-256 loops over 500 MiB, run on the same VM, measured total wall time.
Sandbox samples include Python launcher, systemd, namespace startup and cleanup.

| Sample | Direct process (s) | Offline sandbox (s) |
| --- | ---: | ---: |
| 1 | 1.315680 | 1.463258 |
| 2 | 1.311432 | 1.451019 |
| 3 | 1.303531 | 1.430570 |

Difference between medians: **0.139586 seconds**. The workload executes natively;
this small sample does not isolate steady-state overhead, model concurrent load,
measure container/image startup, or establish paper/proof CI throughput.

## Scope of the result

These measurements establish the tested offline native-command boundary and
restricted host access for the live persistent service. They do not establish
arbitrary-workflow isolation for the registered GitHub runner. Its job steps still
share the persistent service UID, runtime, workspace and runner credentials.
Fresh JIT session placement, controlled egress, image/input/output integration,
and GitHub cancellation wiring remain unfinished. No student workflow was
switched to the offline sandbox, and no repository routing or org policy changed.
