## Audit repairs and negative tests

The installed offline verifier passed 17 checks, including concurrent job
filesystem/process/socket separation, credential exclusion, privilege denial,
background-child cleanup, controller SIGKILL, literal-dollar argv preservation,
and refusing an already-existing explicit unit. Timeout and OOM tests first
observed `PAYLOAD_READY`, then required root receipts with `timeout` and `oom-kill`
respectively, and absent cgroups. The OOM probe used 64 MiB against a 256 MiB
allocation; it did not exhaust the VM. These tests were run before retiring the
legacy service, so its old mount/firewall probes could still be checked.

22 local tests passed, including private/metadata/IPv6/host-subnet address checks,
wrong-peer-UID rejection, DNS-rebinding prevention by dialing only a validated
numeric address, and rejection of unsupported container options. Bash syntax,
ShellCheck, Actionlint and Python compilation passed. Earlier container attempts
failed closed on an upstream hook field-name mismatch, a forced DynamicUser chmod
filter, and the runner's default Docker-socket mount request. The final adapter
handles the live schema, uses fresh locked accounts, and omits Docker socket
exposure. Failed attempts were cleaned; none fell back to host execution.

The November 5 small CPU probe measured native `[2.363, 2.485, 2.761]` seconds and
offline sandbox `[2.347, 2.775, 3.253]` seconds, including setup/teardown. The median
difference was 0.290 seconds. VM contention and small sample size make this
unsuitable as a throughput estimate. No full paper/proof build speedup or slowdown
is claimed. The implementation executes native CPU code; current runner-image
reuse avoids repeatedly downloading that image.
